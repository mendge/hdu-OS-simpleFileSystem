# 扩展练习

下面的练习按难度递增排列。每完成一题，建议在 `tests/run_tests.sh` 中补充相应的测试用例，并用 `stat` 和 `df` 观察块的变化。

## 入门

1. **`rmdir` 命令**：只删除空目录。提示：`fs_remove(s, path, 0)` 已经能拒绝删除非空目录，还需要拒绝删除普通文件。
2. **`ls -a`**：同时显示 `.` 和 `..`，并在每一行前面加上 inode 号。
3. **`passwd` 命令**：修改当前用户的密码。root 可以修改任何用户的密码。
4. **`chown <user> <path>`**：只有 root 可以执行。注意要同时修改 `uid` 和 `gid`。

## 进阶

5. **`mv <src> <dst>` 重命名或移动**。
   - 在同一个目录中重命名时，只需要修改目录项的名字。
   - 移动到另一个目录时：先在新目录中执行 `dir_link`，再在旧目录中执行 `dir_unlink`。如果移动的是目录，还要修改它的 `..` 项。
   - 思考：把 `/a` 移动到 `/a/b` 中会发生什么？应该如何禁止？
6. **`cp <src> <dst>`**：复制文件内容。复制完成后，用 `df` 验证占用的块数翻了一倍。
7. **二级间接索引**：在 inode 中增加 `double_indirect` 字段，并修改 `bmap` 和 `itrunc`。注意 inode 的大小必须保持 64 字节（可以减少一个直接块），`_Static_assert` 会帮你检查。最大文件能达到多大？受 1 MiB 磁盘的限制，又需要做什么调整？
8. **硬链接 `ln <target> <name>`**：在 inode 中增加 `nlink` 链接计数。`rm` 只把计数减 1，减到 0 时才真正释放 inode。思考：为什么大多数系统不允许对目录建立硬链接？
9. **磁盘大小可配置**：把 `NBLOCKS`、`NINODES` 改为格式化时的参数，保存在超级块里，挂载时从超级块读取。位示图需要能够跨越多个块。

## 挑战

10. **块缓存**：在 `disk.c` 之上加一层 LRU 缓存（例如缓存 32 块），统计命中率。思考：直写（write-through）和回写（write-back）各有什么优缺点？回写方式下，程序崩溃会丢失什么？
11. **打开文件表**：实现 `open`、`read`、`write`、`seek`、`close` 这一套接口。每个打开的文件有自己的读写指针，同一个文件可以被打开多次。
12. **崩溃一致性**：在 `disk_write` 中加入"写到第 N 次就退出"的故障注入，观察 `mkdir` 中途崩溃后磁盘处于什么状态（例如 inode 已分配，但目录项还没写入）。然后实现以下两者之一：
    - 一个 `fsck` 命令，扫描并修复不一致；
    - 一个简单的重做日志（redo log）：先把一次操作要写的所有块写入日志区，提交后再写到原位置。
13. **多用户并发**：同时启动两个程序打开同一个镜像，会出现什么问题？可以用文件锁（`flock`/`LockFileEx`）给整个镜像或单个 inode 加锁，实现"多个读者、一个写者"。
14. **密码哈希**：不再保存明文密码，改为保存"随机盐 + 哈希值"。可以自己实现一个简单的哈希函数，并说明为什么它在真实系统中不够安全。
